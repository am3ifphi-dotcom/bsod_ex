# BSOD_EX

短編の一人称ホラー / グリッチ体験。夜の自室で壊れた PC を見つめるところから始まり、青いエラー画面に吸い込まれて、崩壊した 3D 世界を歩いて中心を目指す。所要 15〜25 分、区切りなしのワンカメラ・ワンシーン。

- **エンジン:** three.js r170 + Vite（WebGL2）／物理は Rapier 3D（WASM）
- **言語:** TypeScript 5.6（`strict`）
- **アセット:** Khronos glTF Sample Assets（CC0 / CC-BY-4.0）＋ pmndrs CC0 HDRI＋完全手続き生成のテクスチャ・音
- **テスト:** ヘッドレス 41 件（`npm test`）

> **未検証の明示** — このリポジトリは「GPU もブラウザも無い環境」で作られています。シェーダのコンパイル、実機の fps、実際の描画結果、音の聴感は **一度も実行して確認していません**。詳しくは末尾の [検証できていないこと](#検証できていないこと) を必ず読んでください。

## 1. なぜ Web（three.js + Vite）なのか

| 候補 | 判断 |
| --- | --- |
| **three.js + Vite（採用）** | 単一カメラで「廊下 → モニターへ吸い込まれる → 異世界」をシームレスに行うには、カメラとシーンの完全な制御が必要。three.js はレンダーループ・ポストプロセス・LOD・カスタム GLSL をすべて自前で握れる。ビルドは `vite build` だけで、配布物は静的ファイル。 |
| Unity / Unreal | 品質は出るが、この体験の中心は「1 台のカメラが途切れずに別世界へ移る」ことと「ジオメトリ自体が壊れる」演出。エディタ主体のワークフローに落とすと、その制御をスクリプトから間接的に触ることになり、ビルドサイズも 100 MB 超になる。CI での自動検証も難しい。 |
| Godot | 同上。Web エクスポートは WASM 32 MB 超＋スレッド制約で、ポインタロックや音のレイテンシの検証コストが高い。 |
| 生 WebGL2 | ポストプロセス・影・IBL・LOD をすべて自作することになり、短編 1 本に対して保守コストが見合わない。 |

決め手は 3 つ。**(1)** カメラを 1 台のまま、自室のモニター面 → 異世界へと連続的に移動できる。**(2)** シェーダ差し替え（`onBeforeCompile`）で「ポストだけではない、ジオメトリ / テクスチャ / ライティング側のグリッチ」を直接書ける。**(3)** ビルドが速く、静的ホスティングで動く。

物理は Rapier を使う。キャラクタコントローラ（autostep / 斜面 / スナップ）と地形のトライメッシュ衝突がそのまま使え、three.js のメッシュと 1 対 1 で対応させやすい。

## 2. ビルドと実行

```bash
# 必要環境: Node.js 20.19+ / 22.12+（動作確認は Node 22）
npm install

# アセット（初回のみ。合計 ~24 MB を public/assets/ に生成）
npm run assets:fetch     # Khronos glTF-Sample-Assets + pmndrs/assets を .asset-cache/ へ取得
npm run assets:build     # WebP 化・meshopt 圧縮・LOD 生成・EXR 変換・マニフェスト出力
npm run credits          # assets/credits.json と CREDITS.md を生成

# 開発
npm run dev              # http://0.0.0.0:5173

# 本番ビルド / 確認
npm run build            # tsc --noEmit && vite build  -> dist/
npm run preview          # http://0.0.0.0:4173

# テスト（ヘッドレス 36 件）
npm test
npm test -- nav          # 名前で絞り込み
```

`public/assets/` に生成済みアセットが入っているので、クローン直後は `assets:*` を飛ばして `npm run dev` でも起動します（アセットを作り直す場合のみ fetch → build）。

> WebGL2 と Pointer Lock が必要です。`file://` ではなく `http://` で開いてください。

## 4. 体験の流れ

1. **自室（room）** — 暗い寝室。歩ける範囲は狭い。PC を調べるとカメラが寄り（DOF 有効）、画面に `:(` の BSOD。
2. **BSOD（bsod）** — `:(` をクリックするたびに段階が上がる（3 / 7 / 12 / 18 / 25 クリックで 5 段階）。テキスト破損 → 走査線の崩れ → 顔の輪郭 → 口が開いてポータル化。
3. **吸い込み（consume）** — カメラは 1 台のまま、モニター面の口へ連続的に前進。画面は割れ、世界に切り替わる。
4. **異世界（world）** — 5 つの領域が繋がった一枚マップ（下記）。ロード・フェードなし。
5. **崩壊（collapse）** — 中心の構造物に刻まれた `WAKE_UP` を読んだうえで、コンソールに `WAKE_UP` と入力したときだけ発生する。目 → 頭 → 体の順に視線が動く強制カメラ、ためらい、亀裂の追跡、床の崩落、実ジオメトリの落下、構造物が上方へ退避、プレイヤーも落下。**演出中は入力が完全にロックされ、終了時に戻る。**
6. **帰還（epilogue）** — ベッドルームへ着地（慣性あり）。小さな異変（時計・ポスター・ブラインド）。Esc → 「最初からやり直す」で完全リセット、再プレイ可能。

### 異世界の構成（シームレス一枚マップ）

| 領域 | 位置（m） | 内容 |
| --- | --- | --- |
| A 到着の荒地 | z ≈ +90 | 青い砂、浮遊する断片、巨大な遺物（LOD 2 段） |
| B 崩落した大建築 | x −70…−30, z +10…+60 | 4 層の吹き抜け、入口階段、西面の外付け非常階段、渡り廊下、隠し部屋 |
| C 侵略された都市 | x +24…+78, z −20…+40 | 瓦礫の街路、廃車、割れた窓 |
| D 深層ケーブル層 | y ≈ −9, z ≈ −26 | 溝（トレンチ）、垂れるケーブル、ブロックノイズ |
| E 中心構造物 | 原点 | `WAKE_UP` が刻まれた塔、見張り台、広場 |

地形は 300 × 300 m の高さ関数 1 枚（表示 190 分割 / 衝突 240 分割）。遠景は実際の 3D（LOD + 距離フォグ `FogExp2(0x0a1e42, 0.0128)`）で、板やビルボードではない。

> **仕様との差異:** 「中心まで徒歩 3 分以上」という目標に対し、入り口 → 中心の想定ルートは実測 **約 325 m ≒ 徒歩 75 秒**（ダッシュで約 38 秒）です。世界を 2 倍に広げると地形の衝突メッシュとジオメトリが 4 倍になり、1080p60 の目標と両立しないため、この規模に留めました。

## 5. コンソール（異世界のみ）

`C` で開く。入力はコンソールが完全に保持し、ゲーム側のキー（WASD・E・F など）は動作しない。閉じると元に戻る。

- 実在する風の擬似コマンド: `help` `dir` `cat <file>` `echo` `cls` `whoami` `status` `ver` `sysinfo` `mem` `dump` `time` `date` `credits` `exit` `reboot` `sudo` `open` `glitch` `face`
- 意味のある入力は **`WAKE_UP` だけ**。UI では先に説明されず、世界の側（塔の文字・光・音）から見つける設計。
- それ以外は作中世界のエラーとして返る（例: `reboot` → 「再起動は許可されていません」、`sudo` → 権限エラー、空 Enter → `EMPTY_INPUT`）。
- 崩壊を起こせるのは `WAKE_UP` だけ。UI もコンソールのヘルプもこの語を先に教えないため、塔の文字・光・音から見つける必要があります（読む前でも入力自体は受け付けますが、気づく手がかりは世界の側にしかありません）。

## 6. 描画

- **HDR / リニアワークフロー**、`ACESFilmicToneMapping`、`OutputPass` で sRGB へ。
- **IBL:** `PMREMGenerator` による環境マップ＋自室の CubeCamera 反射プローブのベイク。
- **ポスト:** RenderPass → **GTAO**（SSAO 系、画質プリセットで有効/サンプル数変更）→ **Bokeh DOF**（PC を調べる／吸い込み時）→ **UnrealBloom** → OutputPass → 自作ファイナルパス（フィルムグレイン、ビネット、走査線、色収差、行ティア、タイル破損）。
- **グリッチはポストだけではない:**
  - ジオメトリ: `withGlitch`（`onBeforeCompile`）で頂点を法線方向に脈動・スライス変位。
  - テクスチャ: 地形に記憶グリッドを GLSL で焼き込み、タイル単位の色破損。
  - ライティング: 光源の色温度・強度の揺らぎ、ジオメトリ由来のフリッカー。
- **LOD / インスタンシング:** 遺物は `THREE.LOD` 2 段（近景フル / 遠景 12% ポリゴン）、瓦礫・破片・ブラインド・本・キーボードは `InstancedMesh`。
- **安全:** 1 秒 3 回を超える強い明滅は使わない。全画面ストロボなし。点滅は局所＋低輝度差に限定。

## 7. 音

すべて **Web Audio で実行時合成**（外部サンプル無し）。

- 環境音・ドローンはオシレータ＋ノイズ＋フィルタ。中心構造物のハムは `PannerNode`（HRTF）で空間配置。
- 足音は床材（wood / concrete / metal / sand / carpet）と速度で変化。
- UI 音・サーボ音・亀裂音・落下音も合成。マスターにコンプレッサ／リミッタを入れ、クリップと音量スパイクを防止。`Settings.volume` がマスターに効く。

## 8. アセットパイプライン

```
scripts/fetch-assets.sh  → .asset-cache/  (Khronos glTF-Sample-Assets, pmndrs/assets)
scripts/build-assets.mjs → public/assets/  (glb: weld/dedup/prune, texture→WebP 1024,
                                            EXT_meshopt_compression, LOD1 (12%),
                                            EXR: base64 展開 + 幅高さ検証,
                                            asset-manifest.json, ライセンス同梱)
scripts/gen-credits.mjs  → assets/credits.json + CREDITS.md
```

- 収録: 15 モデル / 23.4 MB、HDRI 6 枚（512×256 EXR）/ 0.8 MB、ライセンス原文 16 ファイル。合計 24.2 MB、およそ 132 万三角形（LOD 含む）。
- **ライセンス:** CC0-1.0 と CC-BY-4.0 のみ。CC-BY のものは作者・出典・原文ライセンスを `CREDITS.md`、ゲーム内 Esc → クレジット、`public/assets/licences/` の 3 か所に残しています。Sponza や VirtualCity など「ライセンスが曖昧／再配布不可」のものは使いません。
- 各モデルの実寸はまちまち（Lantern は約 25 m で作られている等）なので、**配置時に `AssetLoader.fit()` で高さを正規化**しています（世界のスケールは 1 単位 = 1 m）。
- テクスチャは全て手続き生成（Canvas 2D）で、画像ファイルを一切同梱していません。

詳細は [CREDITS.md](CREDITS.md)。再生成は `npm run credits`。

## 9. 性能

**測定値はありません。** この環境にはブラウザも GPU も無いため、実機 fps・1% low は一度も計測できていません（下記「検証できていないこと」）。数値を偽って書くことはしません。

かわりに、目標（1080p / 60 fps / RTX 3050・GTX 1660・M1 クラス）に対して行った設計判断を残します。

- 解像度スケール 0.5〜1.5、**動的解像度**（フレーム時間を見て自動調整）を既定 ON。重い場面で自動的に画素数を落とす。
- 画質プリセット 3 段（低 / 中 / 高）で **GTAO・DOF・Bloom・影解像度・影距離・ライト数・異方性・グレイン**をまとめて切り替え。
- 影: 主要光源のみ、カスケードは使わず距離でフェード。
- ジオメトリ: 遠景は LOD1、瓦礫は InstancedMesh、地形は 1 メッシュ + 距離フォグでオクルージョンカリング頼みにしない。
- 描画コール: 世界 675 オブジェクト / 部屋 106 オブジェクト / 静的コライダ 208 個（マテリアルをキャッシュしてバッチを抑制）。
- WASM（Rapier）は約 2 MB（gzip 761 kB）で、初期ロードに 1 回だけ。ビルド後の `dist/` は three 548 kB + 本体 563 kB + physics 2.06 MB（gzip 合計 ~1.1 MB）。

**自分で測る方法:** `npm run dev` → `F3` で fps / frame time / 1% low / draw call / 三角形数を表示しながら、序盤（room → bsod → consume → world → collapse → epilogue）を通しでプレイしてください。プリセットを切り替えながら同じルートを歩けば比較できます。実測したら README のこの節を実数で置き換えてください。

通常プレイでは無効。`?debug=1`（または `localStorage.setItem('bsod_ex.debug','1')`）で有効化。

- `1` room / `2` bsod / `3` consume / `4` world / `5` core / `6` collapse / `7` epilogue へ即時ジャンプ

## 12. 検証できていないこと

この環境では以下を **実行できていません**。実装はしてありますが「動作確認済み」とは言えません。

- **ブラウザでの起動そのもの。** ヘッドレス Chrome は依存ライブラリ不足で起動できず、WebGL コンテキストを 1 度も作っていません。描画結果・ポストプロセスの見た目・ポインタロック・IME・Pointer Lock 中のキー入力は未確認です。
- **シェーダの GPU コンパイル。** 全 GLSL はパーサで構文検証済み（`shaders.test.ts`）ですが、実際のドライバでのコンパイルと描画は未検証です。three.js のインクルード差し替え（`onBeforeCompile`）も同様。
- **性能測定。** fps・1% low・フレーム時間・draw call の実測値はありません（第 9 節）。
- **音。** 合成パラメータとノードグラフはコード上のみ。聴感、クリップ、音量バランス、空間定位は未確認。
- **通しプレイ。** ストーリー遷移はコードとヘッドレス構築で確認していますが、実際の 15〜25 分のプレイスルーは行っていません。
- **入力の競合。** コンソール/メニュー/ポインタロックの奪い合いはコード上の排他制御のみで、実ブラウザでの確認は未実施。
- **「中心まで徒歩 3 分」は未達**（第 4 節の実測 325 m / 徒歩約 75 秒）。世界の規模は意図的にこの大きさにしています。

## 14. クレジット

[CREDITS.md](CREDITS.md) を参照（モデル・HDRI・ソフトウェア・音・テクスチャの出典とライセンス）。ゲーム内では Esc → クレジット、タイトル画面の「クレジット」からも同じ内容を表示します。
